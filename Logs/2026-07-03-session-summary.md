## 1. New list-management capabilities (backend)

- **Rename a list** — `PATCH /lists/{id}` (custom lists only; core lists protected).
- **Edit a saved item** — `PATCH /lists/{id}/items/{restaurant_id}` for `note` /
  `tags` / `source` (partial update).
- **Core-list mutual exclusivity** — a restaurant is only ever in **Want-to-Try
  XOR Visited**. Adding it to one core list (explicitly, or by recording a visit)
  evicts it from the other. Custom lists stay **additive** — a restaurant can be
  in a core list and any number of custom lists at once. Enforced server-side in
  `add_item` (`app/routers/lists.py`).
- **Multi-visit history** — each `POST /visits` logs a separate row, and
  `GET /visits?restaurant_id=` returns one restaurant's visit history.
- New Pydantic schemas: `ListUpdate`, `ItemUpdate`.

## 2. Dev frontend (test harness)

A single-page vanilla-JS UI at **`/app`**, served same-origin by FastAPI
(`app/static/index.html`) — no CORS, no build step, no Node. Reworked mid-session
per feedback into a **two-page, hash-routed app**:

- **Find Restaurants** (`#/lookup`) — search the Philadelphia seed; each result has
  an **Add to…** picker (core + custom lists) and a **Log visit** button, plus a
  state badge (want-to-try / visited).
- **My Lists** (`#/lists`) — lists sidebar (create / rename / delete) + the selected
  list's items, each with Add to…, edit notes/tags, **Log visit / "Log another
  visit"**, and remove. Includes a visit-logging modal (sentiment / rating / date /
  notes) and per-restaurant visit counts.

Root `/` redirects to `/app/` so the base URL "just works."

## 4. Dev-server hardening (bug fixes)

Chased down a "My Lists is blank" report and a "server keeps crashing" report:

- **Blank items panel** — uvicorn on Windows intermittently resets a keep-alive
  connection under Chrome's rapid requests (`TypeError: Failed to fetch`). Added a
  **retry on transient network errors** in the UI's `api()` helper, an error +
  Retry state instead of a silent blank, and served `/app` with
  `Cache-Control: no-cache` so edits load without a hard-refresh.
- **"Server keeps crashing"** — two launch footguns:
  1. `db.py` used a **relative** `sqlite:///./app.db`, so launching from the repo
     root created a fresh **empty** DB. Fixed by anchoring the default to an
     **absolute** `backend/app.db` (used regardless of CWD).
  2. Plain `--reload` watches the whole tree including `app.db`, so every DB write
     restarted the server mid-request. Documented running from `backend/` **without
     `--reload`** (or with `--reload-exclude "*.db*"`).
- Updated run guidance in `backend/README.md` and `CLAUDE.md`.
